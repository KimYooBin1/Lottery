# QR 기반 결과 사진/녹화 공유 방안

## 목표

게임이 끝난 뒤 한 화면에서 마지막 결과 사진과 게임 참여 장면 녹화를 확인하고 다운로드할 수 있게 한다. 현장 참여자는 QR 코드를 스캔해 같은 결과 페이지에 접근한다.

## 추천 방향

정식 기능은 서버 저장소를 둔 공유 페이지 방식이 적합하다. 브라우저 안에서만 만든 Blob URL은 현재 기기와 현재 세션에서만 유효하므로 QR로 다른 사람에게 전달할 수 없다.

권장 흐름:

1. 게임 시작 시 `MediaRecorder`로 웹캠 스트림 녹화를 시작한다.
2. 결과 확정 시 녹화를 멈추고, 결과 PNG와 녹화 WebM/MP4를 만든다.
3. 두 파일을 업로드 API로 전송한다.
4. 서버는 짧은 `gameId`를 발급하고 파일을 object storage에 저장한다.
5. 앱은 `/result/:gameId` 공유 URL을 만들고 QR 코드로 보여준다.
6. 공유 페이지는 결과 사진, 녹화 재생, 다운로드 버튼, 만료 시각을 제공한다.

## 저장소와 만료

업로드된 사진과 녹화에는 만료 정책이 필요하다. 현장 게임의 성격상 기본 보관 기간은 24시간 또는 7일 중 하나로 정하고, 공유 페이지에 만료 시각을 표시하는 편이 좋다.

가능한 저장소:

- Supabase Storage: 빠른 구현, 인증/DB/스토리지를 한 번에 사용 가능
- Firebase Storage: 브라우저 업로드와 보안 규칙 구성이 쉬움
- Cloudflare R2 + Worker: 비용 효율적이고 짧은 공유 URL 발급에 적합
- GitHub Pages 단독: 정적 호스팅이라 업로드 저장소로는 부적합

## 개인정보와 UX

녹화에는 얼굴과 주변 사람이 포함될 수 있으므로 시작 화면에 녹화 안내와 동의 문구가 필요하다. 결과 화면에는 "녹화 공유"를 명확히 표시하고, 업로드 전 취소 또는 사진만 공유 선택지를 둘 수 있다.

## MVP 단계 제안

1단계는 로컬 결과 화면에서 녹화 미리보기와 다운로드만 제공한다. 이 단계는 백엔드 없이 가능하고, `MediaRecorder` 호환성과 파일 크기를 먼저 검증할 수 있다.

2단계에서 업로드 API, 저장소, QR 코드, 공유 결과 페이지를 추가한다. 이때 파일 만료와 삭제 정책을 함께 넣는다.

3단계에서 QR 페이지에 사진/영상 개별 다운로드, 전체 ZIP 다운로드, 만료 전 삭제 버튼을 추가한다.

## 구현 시 고려 사항

- iOS Safari는 MediaRecorder 지원과 코덱 제약이 있으므로 브라우저별 fallback을 확인해야 한다.
- 녹화 길이가 길어질수록 Blob 메모리 사용량이 커지므로 게임 시작부터 결과까지의 짧은 구간만 기록한다.
- QR 라이브러리는 `qrcode` 또는 `qr-code-styling` 중 하나를 사용한다.
- 업로드 실패 시에도 현재 기기에서 결과 사진/녹화 다운로드는 가능해야 한다.
- 공유 URL은 추측하기 어렵게 랜덤 ID를 사용하고, 만료 후 접근을 차단한다.
